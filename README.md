# ルート上書き権限プロトタイプ

企業向け「ルート上書き権限」の **階層権限 / 承認フロー / 自動監査ログ / 権限マトリクス（who can override what）** を、ローカルで検証するためのプロトタイプです。

対応する PRD: **ルート上書き権限の階層化・監査ログ強化**

> **検証用プロトタイプです。** データはすべてブラウザ内のメモリ上に保持され、バックエンドや本番データには接続しません。認証は行わず、ロール切替で 4 つの役割を疑似体験します。

## 何を検証できるか

PRD の主要ユーザーフローを、ロールを切り替えながら 1 画面で確認できます。

1. **オペレーター** がルート上書きを *提案* する
2. **監督者** が承認キューで *承認 / 却下* する
3. **安全責任者** が *フル上書き（即時適用）* を行い、*監査ログ* を閲覧する
4. **IT / Admin** が *権限マトリクス*（who can override what）を確認する

権限は `src/permissions.ts` の権限マトリクスが唯一の真実（single source of truth）で、UI・状態遷移の両方でこれを強制します（例：オペレーターは承認不可、監督者はフル上書き不可）。

## 権限マトリクス

| 権限 \ ロール        | オペレーター | 監督者 | 安全責任者 | IT / Admin |
| -------------------- | :----------: | :----: | :--------: | :--------: |
| 上書きを提案         | ✓            | ✓      | ✓          | —          |
| 承認                 | —            | ✓      | ✓          | —          |
| 却下                 | —            | ✓      | ✓          | —          |
| フル上書き（即時）   | —            | —      | ✓          | —          |
| 監査ログ閲覧         | —            | —      | ✓          | ✓          |
| 権限管理             | —            | —      | —          | ✓          |

## セットアップと起動

前提: Node.js 18+ / npm

```bash
npm install
npm run dev
```

表示された `http://localhost:5173` をブラウザで開きます。初期状態には確認しやすいようサンプルデータ（提案 1 件・承認済み 1 件・フル上書き 1 件）が入っています。

## 手動での動作確認手順

1. 画面上部のロール切替で **オペレーター** を選び、「上書きの起票」から対象ルート・変更内容・理由を入力して **承認へ提案する**。→ 承認キューに「承認待ち」で追加される。
2. **監督者** に切り替える。「上書きの起票」がフォームではなく提案のみ可能な状態になり、承認キューに **承認 / 却下** ボタンが出る。承認すると「承認済み」になる。
3. オペレーターに切り替え、承認/却下ボタンが表示されない（＝承認権限がない）ことを確認する。
4. **安全責任者** に切り替え、**フル上書き（即時適用）** を実行。承認を経ずに「適用済み」になる。
5. **監査ログ** に、提案・承認・フル上書きが「いつ・誰が・何を」の形で自動記録されていることを確認する（オペレーター/監督者では監査ログはロックされる）。
6. **IT / Admin** に切り替え、**権限マトリクス**で「who can override what」を確認する。

## 自動テスト

権限マトリクスと状態遷移（誰が何をできるか、不正な操作は例外になるか）を `vitest` で検証します。

```bash
npm test         # 一回実行
npm run typecheck # 型チェック（tsc --noEmit）
npm run build     # 型チェック + 本番ビルド
```

## 構成

```
src/
  types.ts            ドメインモデル（Role / Capability / OverrideRequest / AuditEntry）
  permissions.ts      権限マトリクス（single source of truth）と can()
  logic.ts            純粋な状態遷移関数（propose / decide / fullOverride）＋権限強制
  seed.ts             デモ用サンプルデータと対象ルート
  permissions.test.ts 権限・状態遷移のユニットテスト
  App.tsx             画面全体の組み立て（useState で state を保持）
  components/         RoleSwitcher / OverrideForms / ApprovalQueue / AuditLog / PermissionMatrix
```

## スコープ外（今回のプロトタイプで実装しないもの）

- 本番環境へのデプロイ / 本番データ接続 / リポジトリ設定の変更
- 認証・認可基盤（ロールは切替で疑似）
- 監査ログのエクスポート・検索・外部監査システム連携・改ざん耐性
- ルート最適化アルゴリズム、ルート上書き以外の権限体系の再設計
